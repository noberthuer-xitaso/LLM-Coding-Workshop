=== Zweck

Dieses Dokument beschreibt das fachliche Datenmodell und die Zustandsautomaten des Systems _Leihgut_.
Es ergänzt das PRD und den Geschäftsregelkatalog um eine präzise, maschinenlesbar referenzierbare Darstellung aller Domänenentitäten, ihrer Attribute, Beziehungen und erlaubten Zustandsübergänge.

Zweck ist die Grundlage für Implementierung, Datenbankschema, automatisierte Tests und Code-Reviews.
Alle Bezeichner folgen dem Glossar des PRD.
BR-IDs verweisen auf den Geschäftsregelkatalog `business-rules.adoc`.
UC-IDs verweisen auf die Use-Case-Spezifikationen.

=== Zustandsautomat: Gegenstand.zustand

Jeder Gegenstand befindet sich zu jedem Zeitpunkt in genau einem der sechs Zustände.
`ausgemustert` ist ein Endzustand.

[plantuml, zustand-gegenstand, svg]
....
@startuml Zustand_Gegenstand

skinparam StateFontSize 13
skinparam StateBackgroundColor #E3F2FD
skinparam StateBorderColor #1565C0
skinparam ArrowColor #333333
skinparam NoteBackgroundColor #FFFDE7
skinparam NoteBorderColor #F9A825

[*] --> verfügbar : Katalogaufnahme (UC-08)

state verfügbar
state ausgeliehen
state in_Prüfung  as "in Prüfung"
state reserviert
state wartungsfällig
state ausgemustert

verfügbar --> ausgeliehen : Ausgabe\n[BR-05, BR-06, BR-07, BR-08]\n(UC-01)

ausgeliehen --> in_Prüfung : Rückgabe an Theke\n[BR-12]\n(UC-03)

ausgeliehen --> ausgemustert : Verloren erklären\n(ohne Rückgabe)\n[BR-19]\n(UC-07)

in_Prüfung --> verfügbar : Prüfprotokoll abgeschlossen\nnachzustand = verfügbar\nkein Wartungsintervall erreicht\nkeine Vormerkung\n[BR-17, BR-24, BR-30]\n(UC-04)

in_Prüfung --> reserviert : Prüfprotokoll abgeschlossen\nnachzustand = verfügbar\nkein Wartungsintervall erreicht\nVormerkung vorhanden\n[BR-17, BR-24, BR-30]\n(UC-04)

in_Prüfung --> wartungsfällig : Prüfprotokoll abgeschlossen\nnachzustand = wartungsfällig\nWartungsintervall erreicht\n[BR-24]\n(UC-04)

in_Prüfung --> ausgemustert : Prüfprotokoll abgeschlossen\nnachzustand = ausgemustert\noder nachzustand = verloren\n[BR-19]\n(UC-04 / UC-07)

reserviert --> ausgeliehen : Ausgabe an reservierendes Mitglied\n[BR-05]\n(UC-01)

reserviert --> verfügbar : Reservierung verfallen\nkeine weitere Vormerkung\n[BR-31]\n(UC-05)

reserviert --> reserviert : Reservierung verfallen\nnächste Vormerkung vorhanden\n[BR-31, BR-33]\n(UC-05)

wartungsfällig --> verfügbar : Wartung abgeschlossen\nkeine Vormerkung\n[BR-25, BR-26]\n(UC-06)

wartungsfällig --> reserviert : Wartung abgeschlossen\nVormerkung vorhanden\n[BR-25, BR-30]\n(UC-06)

ausgemustert --> [*]

@enduml

=== Zustandsautomat: Ausleihe.status

Eine Ausleihe durchläuft die Zustände `aktiv`, optional `in_Prüfung` und endet in `abgeschlossen`.
`abgeschlossen` ist ein Endzustand.

[plantuml, zustand-ausleihe, svg]
....
@startuml Zustand_Ausleihe

skinparam StateFontSize 13
skinparam StateBackgroundColor #E8F5E9
skinparam StateBorderColor #2E7D32
skinparam ArrowColor #333333
skinparam NoteBackgroundColor #FFFDE7
skinparam NoteBorderColor #F9A825

[*] --> aktiv : Ausgabe\n[BR-09]\n(UC-01)

state aktiv
state in_Prüfung  as "in Prüfung"
state abgeschlossen

aktiv --> in_Prüfung : Rückgabe an Theke\n[BR-12]\n(UC-03)

aktiv --> abgeschlossen : Verloren erklären\n(ohne Rückgabe)\n[BR-19]\n(UC-07)

note on link
  Prüfprotokoll mit nachzustand = verloren;
  Kaution vollständig einbehalten;
  Gegenstand → ausgemustert.
end note

in_Prüfung --> abgeschlossen : Prüfprotokoll abgeschlossen\n[BR-15]\n(UC-04)

note on link
  Kautionsabzug wird festgelegt (BR-21).
  Nutzungszähler +1 (BR-23).
  Gegenstand wechselt Zustand (BR-17).
end note

abgeschlossen --> [*]

@enduml

=== Zustandsautomat: Mitglied.gesperrt (abgeleiteter Zustand)

`gesperrt` ist kein unabhängiger persistierter Zustand, sondern ein **abgeleitetes Prädikat**.
Es wird bei jedem prüfungsrelevanten Ereignis neu bewertet.

[plantuml, zustand-mitglied-sperre, svg]
....
@startuml Zustand_Mitglied_Sperre

skinparam StateFontSize 13
skinparam StateBackgroundColor #FFF3E0
skinparam StateBorderColor #E65100
skinparam ArrowColor #333333
skinparam NoteBackgroundColor #FFFDE7
skinparam NoteBorderColor #F9A825

[*] --> nicht_gesperrt : Mitglied angelegt

state nicht_gesperrt as "gesperrt = false"
state gesperrt       as "gesperrt = true"

nicht_gesperrt --> gesperrt : Ausleihe wird überfällig\n(rueckgabefrist < heute\nUND rueckgabe_datum IS NULL)\n[BR-34, BR-35]

gesperrt --> nicht_gesperrt : Alle überfälligen Ausleihen\nhaben Prüfprotokoll\n[BR-36]

note bottom of nicht_gesperrt
  Darf ausleihen (wenn weitere
  Bedingungen erfüllt, BR-05–08).
  Darf vormerken.
  Darf abholen.
end note

note bottom of gesperrt
  Darf NICHT ausleihen (BR-07).
  Darf vormerken (BR-33).
  Darf NICHT abholen.
  Entstehende Reservierung wird
  übersprungen; Platz bleibt (BR-33).
end note

@enduml
....

=== Invarianten und Constraints

Dieser Abschnitt listet die unveränderlichen Eigenschaften (Invarianten) und Integritätsbedingungen, die das System zu jedem Zeitpunkt einhalten muss.

==== Katalog-Invarianten

[cols="1,4", options="header"]
|===
|ID |Invariante

|INV-01
|`Gegenstand.inventarnummer` ist eindeutig über alle Gegenstände. (BR-01)

|INV-02
|Jeder Gegenstand gehört zu genau einer Kategorie. (BR-01)

|INV-03
|`Kategorie.leihdauer_tage > 0` und `Kategorie.wartungsintervall_ausleihen > 0`. (BR-02)

|INV-04
|`Gegenstand.wiederbeschaffungswert_euro > 0`. (BR-03)

|INV-05
|`Gegenstand.nutzungszaehler ≥ 0`. (BR-23)
|===

==== Ausleihe-Invarianten

[cols="1,4", options="header"]
|===
|ID |Invariante

|INV-06
|`Ausleihe.kaution_betrag_euro` wird bei Ausgabe einmalig berechnet und danach nicht mehr verändert.
Berechnung: `max(5, min(100, round(wiederbeschaffungswert_euro × 0.20)))`. (BR-04, BR-09)

|INV-07
|`Ausleihe.rueckgabefrist = Ausleihe.ausgabe_datum + Kategorie.leihdauer_tage`. (BR-09)

|INV-08
|`Ausleihe.verlaengert = true` kann nur einmal gesetzt werden und nur wenn keine offene Vormerkung für die Kategorie existiert und die Ausleihe nicht überfällig ist. (BR-10, BR-11)

|INV-09
|Ein Mitglied hat höchstens drei aktive Ausleihen gleichzeitig (Status `aktiv` oder `in_Prüfung`). (BR-06)

|INV-10
|Pro Mitglied und Kategorie existiert höchstens eine Vormerkung mit `status = aktiv`. (BR-28)
|===

==== Prüfprotokoll-Invarianten

[cols="1,4", options="header"]
|===
|ID |Invariante

|INV-11
|`Pruefprotokoll.kautionsabzug_euro ≥ 0` und `≤ zugehörige Ausleihe.kaution_betrag_euro`. (BR-21)

|INV-12
|`Pruefprotokoll.vorschaden_pruefprotokoll_id` verweist ausschließlich auf ein Prüfprotokoll desselben Gegenstands (transitiv: über die verknüpfte Ausleihe ermittelbar). (BR-16)

|INV-13
|Zu einer Ausleihe mit `status = abgeschlossen` existiert genau ein Prüfprotokoll, außer beim "Verloren erklären" vor Rückgabe — dort gilt BR-19: `ausleihe_id` ist trotzdem gesetzt, auch ohne vorangegangene Rückgabe. (BR-15, BR-19)

|INV-14
|Der `nachzustand` im Prüfprotokoll wird explizit gesetzt und nicht aus anderen Feldern abgeleitet. (BR-18)
|===

==== Kautionsbewegung-Invarianten

[cols="1,4", options="header"]
|===
|ID |Invariante

|INV-15
|`Kautionsbewegung.betrag_euro > 0`. (BR-22)

|INV-16
|Zu jeder Ausleihe existiert genau eine `Kautionsbewegung` mit `art = hinterlegung` und `pruefprotokoll_id IS NULL`. (BR-20)

|INV-17
|Die Summe aller `abzug`-Bewegungen einer Ausleihe darf `kaution_betrag_euro` der Ausleihe nicht überschreiten. (BR-21)

|INV-18
|Der Saldo aller Kautionsbewegungen einer abgeschlossenen Ausleihe ergibt null:
`hinterlegung − abzug − freigabe = 0`. (BR-20, BR-22)
|===

==== Reservierungs-Invarianten

[cols="1,4", options="header"]
|===
|ID |Invariante

|INV-19
|`Reservierung.verfall_datum = Reservierung.entstehung_datum + 3 Kalendertage`. (BR-31)

|INV-20
|Pro Gegenstand existiert höchstens eine Reservierung mit `status = aktiv`. (BR-30)

|INV-21
|Ein Gegenstand im Zustand `wartungsfällig` hat keine aktive Reservierung und keine aktive Ausleihe. (BR-26)
|===

==== Zustandskonsistenz-Invarianten

[cols="1,4", options="header"]
|===
|ID |Invariante

|INV-22
|Für jeden Gegenstand mit `zustand = ausgeliehen` existiert genau eine Ausleihe mit `status = aktiv`. (Zustandsautomat Gegenstand / Ausleihe)

|INV-23
|Für jeden Gegenstand mit `zustand = in_Prüfung` existiert genau eine Ausleihe mit `status = in_Prüfung`. (Zustandsautomat)

|INV-24
|Für jeden Gegenstand mit `zustand = reserviert` existiert genau eine Reservierung mit `status = aktiv`. (Zustandsautomat)

|INV-25
|`ausgemustert` ist ein Endzustand: Ein Gegenstand mit `zustand = ausgemustert` hat keine aktiven Ausleihen und keine aktiven Reservierungen. (Zustandsautomat)
|===
