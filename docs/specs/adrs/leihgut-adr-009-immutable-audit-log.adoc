= ADR-009: Unveränderliches Audit-Log durch Datenbank-Trigger
:toc: left
:icons: font
:revdate: 2026-08-24

== Status

Accepted

== Context

Every deposit movement, state transition, and actor action must be traceable and tamper-proof.
This is a core quality requirement: the audit trail is the single source of truth for "what happened to this item and this deposit."

Two risks must be mitigated:
. Application bugs or malicious code could accidentally issue `UPDATE` or `DELETE` on audit rows.
. Without a DB-layer guard, the immutability constraint depends entirely on application discipline.

[`src/leihgut/adapters/persistence/schema.sql:93-106`]

== Decision

Enforce audit-log immutability with two DDL triggers on the `audit_log` table:

* A `BEFORE UPDATE` trigger that raises a SQLite error.
* A `BEFORE DELETE` trigger that raises a SQLite error.

Any application code that attempts `UPDATE` or `DELETE` on `audit_log` will receive an `sqlite3.OperationalError` immediately.
Audit entries are written in the same `BEGIN IMMEDIATE` transaction as the domain state change they record, so they are either both committed or both rolled back.

[`src/leihgut/adapters/persistence/schema.sql:96-106`, `src/leihgut/adapters/persistence/sqlite_audit_log_repository.py:17-37`]

Application-layer enforcement only is insufficient because it can be bypassed by direct DB access or a future developer oversight.
An external store adds operational complexity that contradicts the single-process constraint (ADR-004).

== Consequences

*Positive:*

* Immutability is guaranteed at the database layer regardless of application code.
* The constraint is verified by the test suite. [`tests/test_skeleton_01_verfuegbarkeit.py:97-121`]
* No extra infrastructure required.

*Negative:*

* Correcting an erroneous audit entry requires a schema migration (intentional — corrections go into new rows, not edits).
* The triggers are SQLite-specific syntax; migrating to another database requires re-implementing them.

=== Retention Policy

Audit entries older than 90 days are in the "hot window" and available for direct query.
Warm archival is optional and disabled by default.
Cold-tier deletion is not yet implemented (deferred).

[`src/leihgut/anwendungskern/audit_retention_service.py:25-32`, `src/leihgut/anwendungskern/audit_retention_service.py:76-92`]
