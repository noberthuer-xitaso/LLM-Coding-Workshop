Dieses Dokument ist die normative API-Referenz des Systems *Leihgut*.
Es fasst alle REST-Endpunkte und CLI-Kommandos in einer Datei zusammen, sodass Entwickler hier nachschlagen können, ohne jede UC-Datei öffnen zu müssen.

Relevante Quelldokumente: `prd.adoc`, `business-rules.adoc`, UC-01 bis UC-08.

---

== Allgemeine Konventionen

=== HTTP-Konventionen

[cols="1,3"]
|===
|Konvention |Wert

|Base-Path
|`/` (kein Versions-Präfix in Release 1)

|Content-Type
|`application/json` für alle Requests und Responses mit Body

|Zeichencodierung
|UTF-8

|Datumformat
|ISO 8601, Datum: `YYYY-MM-DD`, Zeitstempel: `YYYY-MM-DDTHH:MM:SSZ` (UTC)

|Beträge
|Immer in ganzen Euro (Integer). Keine Dezimalstellen, keine Währungsangabe im Feld.

|IDs
|UUID v4 als String, außer Inventarnummern und Mitglied-IDs (domänenspezifisches Format, z. B. `INV-00042`, `M-0815`)
|===

=== Rollen-Header

Der Header `X-Role` gibt die Rolle des Aufrufers an. Er wird *nicht* kryptographisch geprüft (kein Login im System, vgl. PRD — Authentifizierung). Sein Wert ist informativ und steuert die fachliche Zugangskontrolle.

[cols="1,3"]
|===
|Wert |Bedeutung

|`thekendienst`
|Thekendienst (Karim) — gibt Gegenstände aus und nimmt sie zurück

|`mitglied`
|Mitglied (Sabine) — leiht aus, merkt vor, verlängert

|`wart`
|Werkstattwart (Rolf) — prüft, wartet, ausmustert, erstellt Prüfprotokolle
|===

Fehlt der Header oder trägt er einen unbekannten Wert, verhalten sich Endpunkte mit Rollenanforderung wie in den jeweiligen Fehlerfällen beschrieben.

=== Einheitliches Fehlerformat

Alle Fehlerantworten verwenden dasselbe JSON-Schema:

[source,json]
----
{
  "fehler_code": "FEHLER_CODE_ALS_STRING",
  "beschreibung": "Menschenlesbare Erklärung des Fehlers.",
  "kontext": {
    "feld": "optionale Zusatzinformation, z. B. betroffene ID oder ungültiger Wert"
  }
}
----

Das Feld `kontext` ist optional und kann fehlen, wenn kein Zusatzkontext vorliegt.

=== Zustandsmodell Gegenstände

Ein Gegenstand befindet sich zu jedem Zeitpunkt in genau einem der folgenden Zustände:

[cols="1,3"]
|===
|Zustand |Bedeutung

|`verfügbar`
|Kann ausgegeben oder reserviert werden.

|`ausgeliehen`
|Ausgegeben; Rückgabe steht aus.

|`in_pruefung`
|An der Theke zurückgegeben; Prüfprotokoll steht aus.

|`reserviert`
|Einem Mitglied für drei Kalendertage zugeteilt; Ausgabe steht aus.

|`wartungsfaellig`
|Wartungsintervall erreicht; darf nicht ausgegeben und nicht reserviert werden.

|`ausgemustert`
|Endzustand; verloren oder irreparabel.
|===

=== POST /kategorien

Legt eine neue Kategorie an. Nur Rolle `wart`.

==== Request

[source,http]
----
POST /kategorien HTTP/1.1
Content-Type: application/json
X-Role: wart

{
  "name": "Kettensäge",
  "leihdauerTage": 7,
  "wartungsintervallAusleihen": 10,
  "einweisungspflichtig": true
}
----

[cols="2,1,1,3"]
|===
|Feld |Typ |Pflicht |Beschreibung

|`name`
|string
|ja
|Eindeutiger Name. Nicht leer, max. 100 Zeichen. (BR-02)

|`leihdauerTage`
|integer ≥ 1
|ja
|Leihdauer in Tagen. (BR-02)

|`wartungsintervallAusleihen`
|integer ≥ 1
|ja
|Anzahl Ausleihen bis zur Wartungsfälligkeit. (BR-02)

|`einweisungspflichtig`
|boolean
|ja
|`true` wenn Einweisung erforderlich. (BR-02)
|===

==== Response 201 Created

[source,json]
----
{
  "kategorieId": "KAT-00005",
  "name": "Kettensäge",
  "leihdauerTage": 7,
  "wartungsintervallAusleihen": 10,
  "einweisungspflichtig": true
}
----

==== Fehlerfälle

[cols="1,2,3"]
|===
|HTTP-Status |Fehlercode |Ursache

|400
|`EINGABE_UNGUELTIG`
|Pflichtfeld fehlt, Typ falsch oder Wert außerhalb des erlaubten Bereichs

|403
|`ROLLE_UNZULAESSIG`
|`X-Role` ist nicht `wart`

|409
|`KATEGORIE_NAME_DOPPELT`
|Eine Kategorie mit diesem Namen existiert bereits
|===

==== Request

|boolean
|nein

|===

=== POST /gegenstaende

Legt einen neuen Gegenstand an. Anfangszustand immer `verfügbar`, Nutzungszähler `0`. Nur Rolle `wart`.

==== Request

[source,http]
----
POST /gegenstaende HTTP/1.1
Content-Type: application/json
X-Role: wart

{
  "inventarnummer": "INV-00042",
  "kategorieId": "KAT-00001",
  "wiederbeschaffungswert": 200
}
----

[cols="2,1,1,3"]
|===
|Feld |Typ |Pflicht |Beschreibung

|`inventarnummer`
|string
|ja
|Systemweit eindeutige Inventarnummer. Nicht leer, max. 50 Zeichen. (BR-01)

|`kategorieId`
|string
|ja
|ID der zugeordneten Kategorie. Muss im System existieren. (BR-01, BR-02)

|`wiederbeschaffungswert`
|integer ≥ 1
|ja
|Wiederbeschaffungswert in ganzen Euro. (BR-03)
|===

==== Response 201 Created

[source,json]
----
{
  "inventarnummer": "INV-00042",
  "kategorieId": "KAT-00001",
  "kategorieName": "Bohrhammer",
  "wiederbeschaffungswert": 200,
  "kaution": 40,
  "zustand": "verfügbar",
  "nutzungszaehler": 0
}
----

Das Feld `kaution` ist ein berechnetes Feld (BR-04: 20 % des Wiederbeschaffungswerts, kaufmännisch gerundet, min. 5 €, max. 100 €). Es wird nicht persistiert.

=== PUT /gegenstaende/{inventarnummer}

Aktualisiert Wiederbeschaffungswert und Kategorie eines Gegenstands. Ermöglicht außerdem die Ausmusterung. Nur Rolle `wart`.

==== Klärung Q8 — Kategorienwechsel

Ein Kategorienwechsel (Änderung von `kategorieId`) ist nur erlaubt, wenn der Gegenstand im Zustand `verfügbar` oder `wartungsfaellig` ist.
Bei einem Kategorienwechsel wird der `nutzungszaehler` automatisch auf `0` zurückgesetzt.

*Fehler 422 `KATEGORIENWECHSEL_NICHT_ERLAUBT`*, wenn Kategorienwechsel versucht wird und Gegenstand im Zustand `ausgeliehen`, `in_pruefung` oder `reserviert` ist.

==== Request

[source,http]
----
PUT /gegenstaende/INV-00042 HTTP/1.1
Content-Type: application/json
X-Role: wart

{
  "kategorieId": "KAT-00001",
  "wiederbeschaffungswert": 220
}
----

Für Ausmusterung:

[source,json]
----
{
  "kategorieId": "KAT-00001",
  "wiederbeschaffungswert": 220,
  "zustand": "ausgemustert"
}
----

[cols="2,1,1,3"]
|===
|Feld |Typ |Pflicht |Beschreibung

|`kategorieId`
|string
|ja
|ID der zugeordneten Kategorie. Muss im System existieren. Kategorienwechsel nur bei Zustand `verfügbar` oder `wartungsfaellig` (Q8).

|`wiederbeschaffungswert`
|integer ≥ 1
|ja
|Wiederbeschaffungswert in ganzen Euro. (BR-03)

|`zustand`
|string
|nein
|Nur der Wert `ausgemustert` ist erlaubt. Alle anderen Zustandsübergänge erfolgen über dedizierte Endpunkte.
|===

==== Response 200 OK

[source,json]
----
{
  "inventarnummer": "INV-00042",
  "kategorieId": "KAT-00001",
  "kategorieName": "Bohrhammer",
  "wiederbeschaffungswert": 220,
  "kaution": 44,
  "zustand": "verfügbar",
  "nutzungszaehler": 3
}
----

Bei Kategorienwechsel: `nutzungszaehler` ist `0` in der Response.

==== Fehlerfälle

[cols="1,2,3"]
|===
|HTTP-Status |Fehlercode |Ursache

|400
|`EINGABE_UNGUELTIG`
|Ungültiger Feldwert oder unerlaubter `zustand`-Wert

|403
|`ROLLE_UNZULAESSIG`
|`X-Role` ist nicht `wart`

|404
|`GEGENSTAND_NICHT_GEFUNDEN`
|Kein Gegenstand mit dieser Inventarnummer

|404
|`KATEGORIE_NICHT_GEFUNDEN`
|Kein Kategorie-Datensatz mit der angegebenen ID

|422
|`GEGENSTAND_HAT_AKTIVE_AUSLEIHEN`
|Ausmusterung nicht möglich: Gegenstand ist `ausgeliehen` oder `in_pruefung`

|422
|`KATEGORIENWECHSEL_NICHT_ERLAUBT`
|Kategorienwechsel nicht möglich: Gegenstand ist `ausgeliehen`, `in_pruefung` oder `reserviert` (Q8)
|===

leihgut einweisung dokumentieren --mitglied-id <id> --kategorie-id <id>
----

[source,http]

POST /einweisungen HTTP/1.1
Content-Type: application/json
X-Role: wart

{
  "mitglied_id": "M-0815",
  "kategorie_id": "KAT-00005"
}
----

[cols="2,1,1,3"]
|===
|Feld |Typ |Pflicht |Beschreibung

|`mitglied_id`
|string
|ja
|ID des Mitglieds, das eingewiesen wurde

|`kategorie_id`
|string
|ja
|ID der Kategorie, für die die Einweisung gilt
|===

=== POST /ausleihen

Löst die Ausgabe eines Gegenstands an ein Mitglied aus. Legt die Ausleihe an, hinterlegt die Kaution und versetzt den Gegenstand in den Zustand `ausgeliehen`. Nur Rolle `thekendienst`.

==== Klärung Q9 — Checkout bei Reservierung

Ist der Gegenstand im Zustand `reserviert` *für dieses Mitglied*, akzeptiert das System ihn automatisch als ausgabefähig (BR-05). Die Reservierung wird bei der Ausgabe gelöscht. Es ist kein separater Endpunkt erforderlich.

Ist der Gegenstand für ein *anderes* Mitglied reserviert, schlägt die Ausgabe mit `GEGENSTAND_NICHT_VERFUEGBAR` fehl.

==== Prüfreihenfolge

. Mitglied gesperrt? (BR-07) → `MITGLIED_GESPERRT`
. Aktive Ausleihen ≥ 3? (BR-06) → `AUSLEIHLIMIT_ERREICHT`
. Gegenstand wartungsfällig? (BR-26) → `GEGENSTAND_WARTUNGSFAELLIG`
. Gegenstand verfügbar oder reserviert für dieses Mitglied? (BR-05) → `GEGENSTAND_NICHT_VERFUEGBAR`
. Einweisung vorhanden (falls einweisungspflichtig)? (BR-08) → `EINWEISUNG_FEHLT`

==== Request

[source,http]
----
POST /ausleihen HTTP/1.1
Content-Type: application/json
X-Role: thekendienst

{
  "gegenstandId": "INV-00042",
  "mitgliedId": "M-0815"
}
----

[cols="2,1,1,3"]
|===
|Feld |Typ |Pflicht |Beschreibung

|`gegenstandId`
|string
|ja
|Inventarnummer des auszugebenden Gegenstands

|`mitgliedId`
|string
|ja
|Mitgliedsnummer des ausleihenden Mitglieds

|`ausgabedatum`
|string (ISO 8601)
|nein
|Ausgabedatum; fehlt es, verwendet das System die austauschbare Datumsquelle (BR-09). Darf nicht in der Zukunft liegen.
|===

=== POST /ausleihen/{id}/pruefprotokoll

Erstellt ein Prüfprotokoll, schließt die Ausleihe ab, gibt die Kaution (teil-)frei und versetzt den Gegenstand in den Nachzustand. Nur Rolle `wart`.

==== Klärung Q7 — Schadenszurechnung (Vorschaden-Kontext)

Die Response enthält zusätzlich das letzte Prüfprotokoll desselben Gegenstands unter dem Feld `vorheriges_pruefprotokoll` (kann `null` sein). So sieht der Wart dokumentierte Vorschäden ohne Extra-Abfrage (BR-16).

==== Verarbeitungslogik (transaktional)

. Nutzungszähler um 1 erhöhen (BR-23).
. Effektiven Nachzustand bestimmen:
  * Falls `nutzungszaehler_neu ≥ wartungsintervall_kategorie` → Effektiv: `wartungsfaellig` (BR-24, überschreibt Eingabe).
  * Falls `nachzustand = verloren` → Effektiv: `ausgemustert`, Kautionsabzug = volle Kaution (BR-19).
  * Andernfalls → Effektiv: eingegebener `nachzustand`.
. Kautionsbewegung erzeugen (BR-20, BR-22).
. Gegenstandszustand setzen:
  * `wartungsfaellig` oder `ausgemustert` → Zustand direkt setzen; Warteschlange unberührt (BR-32).
  * `verfügbar` → Offene Vormerkung? Ja → `reserviert` (BR-30, BR-33). Nein → `verfügbar`.

==== Request

[source,http]
----
POST /ausleihen/AL-20260824-00099/pruefprotokoll HTTP/1.1
Content-Type: application/json
X-Role: wart

{
  "nachzustand": "verfügbar",
  "kautionsabzug": 10,
  "begruendung": "Kleiner Kratzer am Gehäuse."
}
----

[cols="2,1,1,3"]
|===
|Feld |Typ |Pflicht |Beschreibung

|`nachzustand`
|string (Enum)
|ja
|Geforderter Nachzustand: `verfügbar` \| `wartungsfällig` \| `ausgemustert` \| `verloren`

|`kautionsabzug`
|integer ≥ 0
|ja
|Kautionsabzug in ganzen Euro. `0` = kein Abzug. Darf hinterlegte Kaution nicht übersteigen (BR-21).

|`begruendung`
|string
|nein
|Freitextbegründung, max. 1 000 Zeichen. (BR-18)
|===

==== Response 201 Created

{
  "pruefprotokoll_id": "pp-9f8e7d6c-5b4a-3210-fedc-ba9876543210",
